# Cloudflare D1 이주 초안 (2026-08-28)

상태: **검토 대기** — 승인 전 착수 없음. 일정은 2026-08-31(월)부터 병행 기준.

## 1. 배경 — 왜 지금 옮기는가

1. **어드민 쓰기 경로가 프로덕션에서 막혀 있다.** Vercel 서버리스 FS는 읽기 전용이라
   관리 기능(구매링크 오버라이드, 제외/복원, 썸네일 관리)을 로컬 `ADMIN_MODE=1`로 돌린 뒤
   freeze → 커밋 → promote 배포까지 거쳐야 반영된다. 실시간 어드민이 되면 이 왕복(건당 ~10분)이 사라진다.
2. **DB-in-git 운송이 수명에 접근 중이다.** 현재 DB는 1.4MB로 작지만, 야간 백필이 1년간 쌓이면
   수백 MB급 바이너리가 되고, 파이프라인이 하루 ~8회 전체 DB를 커밋·푸시한다.
   바이너리는 git 델타가 안 먹히므로 저장소 팽창이 1년 내 감당 불가 수준이 된다.
3. **쓰기 주체 제약.** 한국 VPS는 당분간 불가, 회사 프로젝트라 개인 오라클 인프라도 사용 불가.
   → 수집기(맥)가 어디서든 쓸 수 있는 클라우드 DB가 필요하고, 읽기 주체(Vercel)도 같다.

## 2. 결정 사항과 비목표

- **옵션 A만 진행**: 앱은 Vercel 유지, DB만 Cloudflare D1로. (옵션 B = 앱까지 Workers 이주는 +3~5일, 실익 없음 → 배제)
- Vercel 선택은 실수가 아니었다는 전제 확인: 빠른 배포라는 당시 목표에 맞았고,
  이번 이주는 호스팅 교체가 아니라 데이터 계층 추가라 Vercel 투자가 그대로 살아있다.
- **비목표**: 스냅샷 HTML은 D1에 넣지 않음(로컬 디스크 유지), 터소/네온 등 대안 재검토 없음,
  수집 로직 자체 변경 없음.

## 3. 대상 아키텍처

```
[수집 맥]  collect.py → 스냅샷 HTML(로컬)
           ingest-*.ts ──(D1 HTTP API)──┐
[Vercel]   page/쿼리 읽기 ───────────────┤→ Cloudflare D1 (hotdeal)
           어드민 API 쓰기(실시간) ───────┘
배포 = 코드만 푸시 → Vercel (freeze/DB커밋/promote 절차 폐기)
```

- 접근 방식: D1 bindings는 Workers 전용이므로 **D1 REST API** 사용
  (`POST /client/v4/accounts/{acc}/d1/database/{id}/query`, sql+params, 배열 배치 지원).
- 자격증명: `CF_ACCOUNT_ID` / `CF_D1_DATABASE_ID` / `CF_API_TOKEN`(D1 편집 권한) —
  Vercel env + 로컬 `.env.local`에만. 코드·커밋 이식 금지(네이버 광고 키 선례).

## 6. 리스크와 대응

1. **읽기 지연** — 페이지 렌더가 쿼리 여러 개면 HTTP 왕복이 곱해진다.
   대응: D0에서 실측, 렌더당 1~2회로 SQL 배치(`query`에 배열 전달), 필요 시 `Promise.all` 병렬.
2. **무료 한도** — 5GB 저장 / 일 500만 행 읽기 / 일 10만 행 쓰기.
   읽기는 내부 트래픽이라 여유. 쓰기는 백필 과부하 밤 추정 4~6만 행으로 상한의 40~60% —
   여유는 있지만 대시보드 알림(80%) 걸어두고, 초과 징후 시 유료(사용량 과금, 월 수 센트 수준) 전환 기준 사전 합의.
3. **트랜잭션 시맨틱** — REST 배치에서 `BEGIN…COMMIT`이 원자적으로 도는지 D0에서 검증.
   미지원이면 인제스트는 본래 멱등이라 부분 실패 허용으로 재구성(스크립트 재실행으로 복구).
4. **토큰 유출** — env 전용, 코드/문서에 값 박기 금지, 유출 의심 시 즉시 롤 후커 발행.
5. **커트오버 직후 회귀** — 롤백 배포는 가능하지만 롤백 시점 이후 D1에 들어간 쓰기는
   로컬 파일에 없음(수 시간 분 손실 허용 전제). 첫 주에는 야간 백필 후 행 수 대조를 일과로.
